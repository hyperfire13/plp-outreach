1. About the System

The PLP Community Outreach Management System is a centralized platform for planning, documenting, reviewing, and reporting the university's community extension work. It connects community needs, outreach initiatives, individual participation, project applications, approvals, and institutional monitoring in one role-controlled system.

1.1 Main objectives

  • Maintain reliable records of communities, programs, projects, accomplishments, participants, and proposals.
  • Base extension project applications on validated community needs.
  • Give each qualified user an individual, verified community engagement portfolio.
  • Support multi-level review, accountability, reporting, accreditation, and institutional evaluation.
  • Protect sensitive operations through authentication, server-side authorization, rate limits, audit logs, and scoped data access.

1.2 The four modules

ModulePurposeMain outputs
Module 1: Outreach ManagementMaintains outreach program categories, operational projects, and accomplishment records.Program catalog, project records, execution and impact data.
Module 2: Community Needs AssessmentRegisters communities, designs surveys, records responses, ranks needs, and validates priority needs.Submitted assessments and validated community needs.
Module 3: Community Engagement ProfilesRecords verified participation by faculty, staff, students, and other authorized users.Grouped engagement activities, service hours, analytics, and downloadable profile PDF.
Module 4: Project ApplicationsCreates need-based extension proposals and routes them through institutional approval.Approved proposal, approval history, notifications, supporting files, and Notice to Proceed.

1.3 How the modules relate

Community Registration → Survey → Submitted Response → Priority Need Validation → Project Proposal → Multi-level Approval → Notice to Proceed → Outreach Implementation → Accomplishment Record → Engagement Profiles and Reports
  • Module 2 supplies the validated need required by Module 4.
  • Module 4 authorizes a proposed intervention and prepares it for implementation.
  • Module 1 records operational programs, projects, and actual accomplishments.
  • Module 3 records the people who participated and builds their verified portfolios.
  • The Dashboard summarizes role-relevant data from the modules.
  • The Audit Trail records successful write operations for accountability.
Important: Menu visibility is not the only security control. Laravel also checks roles, ownership, college scope, record status, and workflow stage. Typing a protected URL does not bypass authorization.

2. Getting Started

2.1 Signing in

  1. Open the system URL in a supported web browser.
  2. Enter the PLP account email and password assigned by an administrator.
  3. Select Sign in.
  4. The system loads the Dashboard and the sidebar options permitted for the account's role.

Repeated failed login attempts may be temporarily rate-limited. Contact an administrator if credentials are unknown or the account requires correction.

2.2 Main navigation

  • Top navigation: sidebar toggle, Home, notification bell, fullscreen control, current user, profile, and sign out.
  • Settings: administrative, outreach management, community assessment, and audit options available to the current role.
  • Project Applications: need-based proposals and approvals for authorized users.
  • Community Engagement: engagement records and the user's own engagement profile.

The selected page is highlighted. Parent groups remain open when one of their child pages is active. On mobile devices, the sidebar closes after navigation.

2.3 Updating your profile

  1. Select the user name or person icon in the upper-right corner.
  2. Select My Profile.
  3. Update permitted personal fields and save.
  4. Use the password section to change the password. The current password is required.
Can: update personal profile details and password. Cannot: change personal role or college through the profile page. Those are controlled by authorized user managers.

2.4 Notifications

The bell icon shows unread workflow notifications, especially Module 4 proposal reviews and Notice to Proceed availability. Open a notification to mark it read and navigate toward the related feature. Use Mark all read to clear the unread count.

2.5 Signing out

Open the user menu and select Sign out. The active API session is revoked and the user returns to the login page. Always sign out on shared devices.

3.1 General permission rules

  • View permission does not automatically provide create, edit, delete, validate, or approve permission.
  • Ownership: several records can only be edited or deleted by their creator.
  • College scope: college administrators and similar roles generally operate within their assigned college.
  • Status: submitted, approved, or completed records may be locked against editing.
  • Workflow stage: Module 4 only allows the role assigned to the current stage to act.

4. Shared Features

4.1 Dashboard

The Dashboard is role-aware. It may show outreach project totals, verified engagements, verified service hours, survey responses, priority needs, accomplishments, communities, programs, project status summaries, pending engagement reviews, and recent records.

Counts follow the user's authorized data scope. A college user may see only relevant college or assigned records, while institutional administrators may see broader totals.

4.2 Search, filters, and pagination

  • Use search fields for names, titles, identifiers, or descriptions supported by the page.
  • Apply status, type, date, year, community, college, SDG, or module filters when available.
  • Use pagination controls at the bottom of tables. Page totals are provided by the Laravel API.
  • Reset filters when a record appears missing.

4.3 PDF downloads

  • Blank survey forms can be downloaded from published survey templates.
  • Verified engagement profiles can be downloaded as portfolio PDFs.
  • Approved Module 4 proposals with an issued NTP can download the Notice to Proceed PDF.

PDF endpoints are rate-limited. Repeated rapid downloads may require waiting before trying again.

5. Module 1: Outreach Management

Module 1 maintains the operational structure and results of PLP outreach. It contains Outreach Programs, Outreach Projects, and Accomplishment Records.

5.1 Outreach Programs

An Outreach Program is a reusable institutional program category or framework. Fields include name, category, description, typical budget, typical duration, active status, and creator.

Who can access?

  • View: Super Administrator, CALO Administrator, College Administrator, Faculty Extension Coordinator.
  • Create: Super Administrator, College Administrator, Faculty Extension Coordinator.
  • Edit/Delete: only the user who created the program.

Basic workflow

  1. Open Settings → Outreach Programs.
  2. Select Add Program.
  3. Enter required information and save.
  4. The creator's name appears in the table.
  5. Edit or delete buttons appear only when the current user owns that record.

5.2 Outreach Projects

An Outreach Project is an operational initiative linked to an outreach program and college. It can capture title, description, objectives, location, schedule, proposed budget, expected beneficiaries, coordinator, members, community partners, evaluators, and status.

Who can do what?

  • Create: Super Administrator, CALO Administrator, Project Proponent, Faculty Extension Coordinator.
  • View: administrators; the creator; authorized same-college leaders; assigned members, evaluators, and community partners.
  • Edit: administrators, or the owner while status is Draft or Returned.
  • Delete: administrators, or the owner while status is Draft.
Cannot: an unassigned user cannot open another project's protected details merely by typing its URL. An owner cannot edit a locked project status unless the policy allows it.

5.3 Accomplishment Records

Accomplishment Records document actual outreach execution and results. They capture community, outreach program, college, budget used, volunteers, impact score, success rate, satisfaction rating, execution date, and creator.

  • View: Super Administrator, CALO Administrator, College Administrator, Project Proponent, Faculty Extension Coordinator, College/Department Head, Monitoring and Evaluation Team.
  • Create: Super Administrator, CALO Administrator, College Administrator, Project Proponent, Faculty Extension Coordinator.
  • Edit/Delete: administrators, the creator, or a same-college College Administrator.

Accomplishments support dashboard reporting and provide evidence for actual program implementation. Engagement records may also reference an outreach project to document individual participation.

6. Module 2: Community Needs Assessment

Module 2 identifies and validates community needs. It is the required source of evidence for Module 4 proposals.

6.1 Communities

The community registry stores the location and identity of partner communities used by surveys, needs, accomplishments, engagement records, and proposals.

  • Manage communities: Super Administrator, CALO Administrator, College Administrator.
  • Lookup/use communities: selected outreach, assessment, partner, and monitoring roles.
  • Cannot: users outside the community management group cannot create, edit, or delete community master records.

6.2 Survey Templates and Questions

A Survey Template defines an assessment instrument. Its questions may be organized by section and can use text, textarea, number, date, Boolean, select, radio, or checkbox response types.

  • Design templates/questions: Super Administrator and CALO Administrator.
  • Statuses: Draft, Published, Archived.
  • Download blank form: authorized survey respondents can download a published template PDF.

Designer workflow

  1. Create or edit the template.
  2. Add questions, required flags, choices, section names, help text, and order.
  3. Review before publishing.
  4. Publish for field use or archive when retired.

6.3 Survey Responses

Authorized survey respondents can encode assessment data for a selected community and survey template.

  • Respondents: Super Administrator, CALO Administrator, College Administrator, Faculty Extension Coordinator, Community Partner, Monitoring and Evaluation Team.
  • Draft: can be saved and edited before submission.
  • Submitted: becomes the source for priority-needs analysis.
Select Community + Template → Answer Questions → Record Priority Needs → Save Draft → Review → Submit

6.4 Priority Needs

Priority Needs are ranked concerns extracted from submitted surveys. Users can filter by community, need, rank, year, and month and view summary counts and average ranks.

  • View: Super Administrator, CALO Administrator, College Administrator, Project Proponent, Faculty Extension Coordinator, College/Department Head, Community Partner, Monitoring and Evaluation Team.
  • Validate/Reject: Super Administrator, CALO Administrator, Monitoring and Evaluation Team.
  • Validation result: Validated needs become selectable in Module 4.
Critical rule: a project proposal cannot be submitted without an existing validated community need. Pending or rejected needs cannot be used to satisfy the Module 4 gate.

7. Module 3: Community Engagement Profiles

Module 3 records and verifies the community engagement contributions of PLP users. Each approved participant row contributes to that person's engagement portfolio.

7.1 Engagement records

An engagement activity includes a title, participants, engagement type, participation role, date, service hours, SDG alignment, description, source, optional outreach project/community, and workflow status.

When a College Administrator selects multiple participants, the system stores participant entries under one grouped activity. The table displays all participants as a list and paginates by activity rather than by participant row.

Who can access?

  • View engagement features: all defined roles, subject to record-level scope.
  • Encode: Super Administrator, CALO Administrator, College Administrator, Coordinator, Project Proponent, Faculty Extension Coordinator.
  • Approve/Reject submitted records: Super Administrator, CALO Administrator, Monitoring and Evaluation Team.

Status workflow

Draft or Rejected → Edit Participants/Details → Submit → Submitted → Approve or Reject → Approved or Rejected
StatusMeaningWhat is allowed?
DraftStill being prepared.Authorized manager can edit, change participant checklist, delete, or submit.
SubmittedWaiting for validation.Locked against ordinary editing; reviewer may approve or reject.
ApprovedVerified institutional engagement.Included in profile totals, service hours, analytics, and PDF.
RejectedReturned with validation remarks.Authorized manager can correct and resubmit.

Creating a grouped engagement

  1. Open Community Engagement → Engagement Records.
  2. Select Add Record.
  3. For College Administrators, search and check one or more participants.
  4. Enter activity information and choose Draft or Submit for Validation.
  5. Save. Participants appear together under one activity.

Editing participants

  1. Open an editable Draft or Rejected activity.
  2. The checklist automatically marks current participants.
  3. Check additional participants or uncheck removed participants.
  4. Save. The system synchronizes additions/removals atomically and avoids duplicates.

7.2 Individual engagement profile

The profile shows verified activities, total engagements, service hours, filters, and portfolio information. Users can view their own profile; administrators and monitoring roles have broader access; college leaders may view users within their college.

  • Only Approved records count as verified achievements.
  • Use available filters such as year, SDG, engagement type, and other profile criteria.
  • Select the PDF action to download a portfolio suitable for reporting or accreditation.
Can: download a verified portfolio. Cannot: make a Draft, Submitted, or Rejected activity appear as verified simply by viewing the profile.

8. Module 4: Community Extension Project Applications

Module 4 manages the proposal lifecycle from need-based draft through final approval and Notice to Proceed.

8.1 Who can access and apply?

  • Viewers: Super Administrator, CALO Administrator, CALO Staff, College Administrator, Coordinator, Project Proponent, Faculty Extension Coordinator, College/Department Head, Student/Volunteer, Academic Affairs Officer, VPAA, University President.
  • Applicants: College Administrator, Coordinator, Project Proponent, Faculty Extension Coordinator, Student/Volunteer, provided the user has an assigned college.
  • Visibility: applicant, same-college authorized users, and institutional users without college scope can view eligible proposals.

8.2 Proposal contents

  • Validated priority need and affected community
  • Title and rationale
  • Objectives and beneficiaries
  • Expected outputs and outcomes
  • Sustainability plan and risk assessment
  • Monitoring indicators
  • SDG and development-plan alignment
  • Partner involvement and proposed budget
  • Resources and workplan information supported by the API data model
  • Supporting documents: MOA, letter, budget, workplan, or other accepted office files

8.3 Applicant workflow

  1. Open Project Applications.
  2. Select Add Proposal.
  3. Select a validated community need. If none is available, coordinate with Module 2 reviewers.
  4. Complete required narrative, alignment, and budget fields.
  5. Save as Draft.
  6. Open the proposal to upload supporting documents if required.
  7. Select Submit. The proposal enters Immediate Head/Dean review.
  8. If revision is requested, edit the proposal and submit again.

The applicant may edit or delete only an owned proposal in Draft or Revision Requested status.

8.4 Approval sequence

OrderWorkflow stepAuthorized rolePurpose
1Immediate Head / DeanCollege/Department Head from the proposal's collegeNotation and college-level review
2CALO StaffCALO StaffCompleteness and compliance screening
3CALO HeadCALO AdministratorFirst-level approval and endorsement
4Academic Affairs OfficerAcademic Affairs OfficerAdditional Academic Affairs review
5VPAAVice President for Academic AffairsEndorsement to the President
6PresidentUniversity PresidentFinal institutional approval

At each active stage, the assigned reviewer can:

  • Approve/Endorse: advance to the next stage.
  • Request Revision: return to the applicant for correction; remarks are required.
  • Reject: end the review as rejected; remarks are required.
Cannot: a reviewer cannot approve out of sequence, approve while another role owns the current stage, or use a copied URL to bypass the stage policy.

8.5 Notice to Proceed

After presidential approval, the Super Administrator or CALO Administrator can issue the NTP. The proposal status becomes NTP Issued, the applicant receives a notification, and authorized viewers can download the NTP PDF.

8.6 Proposal statuses

9. Administration and Audit Trail

9.1 User management

  • Managers: Super Administrator, CALO Administrator, College Administrator.
  • Super and CALO administrators can manage users broadly.
  • College Administrators can view, create, and update users within their own college.
  • Only institutional administrators can delete another user; a user cannot delete the currently signed-in account.
  • Role and college assignments must be maintained through authorized user management, not the personal profile page.

9.2 College management

Super Administrator and CALO Administrator maintain the college master list. Other users may use college data as permitted but cannot modify the master records.

9.3 Audit Trail monitoring

The Audit Trail is a read-only monitoring page available to Super Administrator and CALO Administrator through Settings → Audit Trail.

Information recorded

  • Activity/action and module
  • Person who performed the action, or System when no actor is available
  • Date and time
  • Route, HTTP method, IP address, request ID, and user agent
  • Previous and submitted values when recorded

Using the page

  1. Search by activity, user, IP address, or request ID.
  2. Filter by module, action, start date, and end date.
  3. Select View to inspect complete request context and value snapshots.
  4. Use Refresh to load recent activity or Reset to clear filters.
Security: password, confirmation, current-password, token, and authorization fields are redacted by the audit service. Audit entries cannot be edited through the UI.

10. End-to-End System Flow

  1. Administration: set up colleges, roles, users, and communities.
  2. Assessment preparation: CALO designs and publishes a survey template and questions.
  3. Field assessment: an authorized respondent selects a community, completes the survey, ranks needs, and submits it.
  4. Need review: authorized reviewers validate or reject priority needs.
  5. Proposal preparation: an eligible applicant selects a validated need and writes the Module 4 proposal.
  6. Approval: the proposal follows Head/Dean → CALO Staff → CALO Head → Academic Affairs Officer → VPAA → President.
  7. Implementation authorization: CALO issues the Notice to Proceed.
  8. Operational tracking: authorized users maintain related programs, projects, and implementation records.
  9. Accomplishment: budget, volunteer, impact, success, satisfaction, and execution information is recorded.
  10. Individual engagement: participant activities are encoded, submitted, and verified.
  11. Reporting: dashboards, engagement profile PDFs, survey PDFs, NTP PDFs, and audit monitoring support evaluation and accreditation.

12. Troubleshooting and Good Practices

SituationWhat to check
A menu is missingConfirm the account role. The sidebar intentionally hides features outside the role group.
Forbidden when opening a URLThe server rejected the role, scope, ownership, status, or workflow stage. Request the correct assignment; do not try to bypass it.
No need is available in a proposalThe need must come from a submitted assessment and have Validated status.
Cannot edit a recordCheck ownership and status. Submitted/approved records are commonly locked.
Cannot approve a proposalConfirm the proposal is Under Review and currently assigned to your exact workflow stage.
Engagement missing from profile totalOnly Approved engagement records are verified and counted.
PDF download temporarily failsWait and retry; PDF endpoints are rate-limited. Also confirm authorization and that the required output exists.
Changes do not appearRefresh the page, reset filters, and confirm the save request completed without validation errors.

12.1 Data-quality practices

  • Search for an existing community, user, program, or project before creating another.
  • Use clear activity and proposal titles.
  • Verify dates, service hours, participant selections, budgets, and college assignment before submission.
  • Write specific revision/rejection remarks so the record can be corrected.
  • Upload only relevant, authorized, and safe supporting documents.
  • Do not share passwords or leave sessions open on shared computers.
